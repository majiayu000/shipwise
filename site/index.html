The discoverability gate

# hand the Shipwise record to the execution layer
python3 scripts/repo_seo_baseline.py \
  --root  /path/to/target-repo \
  --project-yaml shipwise/projects/ccstats/project.yaml \
  --json

# the gate refuses to pass on missing evidence
"status": "error",
"errors": [{
  "surface": "shipwise",
  "check":   "social_image_set",
  "reason":  "social preview image is not marked as set"
}]
# exit code 1  — fix the record, not the gate

The discoverability: block in every project record is a machine-checkable contract: description, primary keyword, 5–20 GitHub topics, homepage URL, social preview state, license, contributing guide, and support path.

Failures land in a structured errors array with a non-zero exit code — CI and launch-readiness reviews fail closed instead of silently shipping an unfindable repo.

04

Four audit skills

github-repo-seo

Repo metadata, README first screen, package registries, release verification, Search Console handoff boundaries.

technical-seo-audit

Crawlability and page-level evidence: title, meta, canonical, OG cards, JSON-LD, robots.txt, sitemap.xml — with soft-404 detection.

seo-content-geo

Keyword maps, content briefs, GEO/AEO readiness, and AI-citation shape — every claim tagged Confirmed, Likely, or Hypothesis.

seo-data-sources

Chooses the smallest data source that proves the claim; records access status and cost before any paid provider is trusted.
